# Contract Lab: контрактное тестирование API с расширениями

Лабораторная работа «Программа с расширениями». Основная программа написана на **Java 17**,
контракты — на **Lua**, интерпретатор внутри JVM — **LuaJ**. JSON разбирается библиотекой Jackson.

Программа проверяет ответ API по ожиданиям потребителя: HTTP-статус, Content-Type,
наличие и типы полей, ограничения значений. Например, клиент ожидает пользователя с
числовым `id`, непустым `name` и целочисленным `age >= 18`.
Правила находятся в `contracts/user.lua`, а не в Java-коде.

Это учебная проверка ответа провайдера по исполняемому контракту потребителя.
Здесь нет брокера контрактов, генерации моков и согласования версий между сервисами.

## Быстрый старт

Нужны JDK 17+ и Maven 3.9+. Для первой сборки нужен интернет, чтобы Maven скачал зависимости.
Lua отдельно устанавливать не нужно. Все команды выполняются из корня `contract-lab`.

```sh
mvn clean verify
java -jar target/contract-lab.jar
```

Ожидаемый результат (время будет другим):

```text
12:00:00 PASS — Контракт пользователя выполнен
```

В `target/contract-lab.jar` упакованы Java-классы и зависимости. Lua-контракты остаются
внешними файлами. Если в архиве уже есть этот JAR, его можно запустить с Java 17+
без Maven и без интернета. Для собственной сборки и запуска тестов используйте команду выше.

Некорректный ответ:

```sh
java -jar target/contract-lab.jar --file examples/user-invalid.json
```

Результат: `FAIL — id должен быть положительным целым числом`.
Коды завершения: **0** — PASS, **1** — FAIL, **2** — ERROR.
FAIL означает нарушение контракта; ERROR — ошибку скрипта, входного JSON, чтения или HTTP-запроса.

## Главное: изменение без перекомпиляции и перезапуска

1. Соберите проект один раз: `mvn clean verify`.
2. Запустите:

   ```sh
   java -jar target/contract-lab.jar --watch
   ```

3. Пока Java работает, откройте `contracts/user.lua` в редакторе.
4. Замените `local MIN_AGE = 18` на `local MIN_AGE = 21` и сохраните.
5. Следующая проверка выдаст `FAIL — age должен быть целым числом не меньше 21`.
6. Верните `18`: снова появится PASS. Не запускайте Maven и не перезапускайте Java.
7. Остановите программу сочетанием Ctrl+C.

В примере возраст равен 20. Меняется именно выполняемый код расширения, а не Java-класс.
Режим watch каждые 1000 мс после завершения предыдущей проверки повторно читает Lua и JSON
(или снова делает HTTP GET). При каждом цикле Lua загружается в новое окружение.
Это простая периодическая перезагрузка, без файловых событий и кеша: она работает и
с обычным сохранением файла, и с заменой файла редактором, и с Docker bind mount.
Интервал задаётся через `--interval 500`. Он не включает время HTTP-запроса и проверки.

## Ошибка в расширении и восстановление

В режиме `--watch` временно замените тело `validate` на:

```lua
function validate(user, response)
    error("Демонстрационная ошибка")
end
```

Программа напечатает ERROR и продолжит цикл. Восстановите исходный скрипт — снова получите PASS.
Синтаксические ошибки, отсутствие `validate`, неправильные типы возвращаемых значений,
ошибочный JSON и недоступность источника также превращаются в ERROR.
При ошибке применяется текущий результат ERROR; старый успешный контракт не используется скрыто.

## Проверка настоящего HTTP-ответа

В первом терминале запустите демонстрационный API, написанный в этом проекте:

```sh
java -jar target/contract-lab.jar --demo-server 8080
```

Во втором терминале:

```sh
java -jar target/contract-lab.jar --url http://127.0.0.1:8080/users/42 --watch
```

Можно менять `MIN_AGE` и наблюдать PASS → FAIL без перезапуска клиента или сервера.
Два дополнительных маршрута показывают нарушения:

```sh
java -jar target/contract-lab.jar --url http://127.0.0.1:8080/users/broken
java -jar target/contract-lab.jar --url http://127.0.0.1:8080/users/unavailable
```

Первый возвращает строковый `id` вместо числа. Второй — HTTP 503 с JSON-телом.
Оба дают FAIL. Сервер слушает только `127.0.0.1`; Ctrl+C завершает его.
В `--url` можно передать собственный HTTP(S) API. Выполняется GET без авторизации и
автоматического следования перенаправлениям. Таймаут подключения — 5 с, запроса — 10 с.

## Другое расширение без изменения Java

```sh
java -jar target/contract-lab.jar --contract contracts/order.lua --file examples/order.json
```

Этот контракт проверяет позиции заказа и равенство `total` сумме `price * quantity`.
Условия, циклы и вычисления выполняются в Lua. Можно добавить новый файл `.lua` с тем же
интерфейсом и передать его через `--contract` — Java-движок не меняется.

## Интерфейс расширения

```lua
function validate(body, response)
    -- body: разобранное JSON-тело
    -- response.status: HTTP-код
    -- response.headers: заголовки со строчными именами
    return true, "Контракт выполнен"
end
```

Функция обязана возвращать два значения: `boolean` и `string`.
`true` означает PASS, `false` — FAIL. Число `1` или строка `"true"` вместо boolean — ERROR.
Для файлового источника используются условные статус 200 и Content-Type `application/json`:
это проверка сохранённого тела, а не реальных HTTP-метаданных.

| JSON | Lua |
|---|---|
| Объект | Таблица с ключами-строками |
| Массив | Таблица с индексами от **1** |
| Строка / boolean | `string` / `boolean` |
| Число | `number` |
| `null` | Специальное значение `JSON_NULL` |
| Отсутствующее поле | `nil` |

`JSON_NULL` сохраняет null-элементы массивов и позволяет отличить `{"x":null}` от `{}`:
`body.x == JSON_NULL` и `body.x == nil` — разные проверки.
Пустой объект и пустой массив в этом простом мосте оба становятся пустой таблицей.
Числа представлены с точностью double; целые за пределами ±(2^53−1) отклоняются,
чтобы контракт не проверял незаметно округлённый идентификатор. Большие ID передавайте строками.
Дроби подвержены обычному округлению double: для денежных расчётов предпочтительны целые копейки.
Повторяющиеся ключи JSON и посторонние данные после JSON отклоняются.

## Устройство программы — для защиты

1. `Main` разбирает параметры и выбирает источник. В watch он повторяет проверку в одном JVM-процессе.
2. `ResponseSource` читает UTF-8 файл или делает HTTP GET через стандартный `HttpClient`.
3. `ContractRunner.check` читает **внешний** Lua-файл через `Files.readString` и разбирает JSON с Jackson.
4. `JsePlatform.standardGlobals()` создаёт окружение встроенного LuaJ.
5. `globals.load(script, "@" + contract).call()` загружает и исполняет верхний уровень скрипта,
   на котором объявляется функция `validate`.
6. `globals.get("validate")` получает функцию. `JsonToLua.convert` рекурсивно преобразует JSON.
7. `validate.invoke(...)` вызывает Lua-код, передавая тело и метаданные. `Varargs` содержит два результата.
8. Java проверяет типы результатов и выводит PASS/FAIL. Исключения преобразуются в ERROR,
   а следующий цикл продолжает работу с заново прочитанным расширением.

**Почему Java не надо перекомпилировать?** Её код содержит механизм вызова, но не условия
вроде минимального возраста. Эти условия читаются из Lua-файла во время работы.
LuaJ преобразует текст Lua во внутренние инструкции и исполняет их в JVM;
Java-классы и JAR при редактировании расширения не изменяются.

**Где основная программа, а где расширение?** Основная программа — наши Java-классы.
Расширения — отдельные `contracts/*.lua`, исполняемые встроенной библиотекой LuaJ.
Это скриптовое расширение, а не нативная библиотека через dlopen/LoadLibrary.

**Что такое контракт в этом проекте?** Ожидания клиента к ответу провайдера. Например,
замена числового `id` на строковый ломает контракт, даже если HTTP-запрос успешен.
Проверка возраста — дополнительное предметное ограничение.

**Чем конфигурация отличается от этого расширения?** Lua-файл содержит исполняемую функцию:
ветвления, циклы, вычисления и произвольные дополнительные проверки.

**Какие ошибки обрабатываются?** Обычные ошибки Lua, парсинга и ввода-вывода.
Это учебный запуск доверенных локальных скриптов: стандартные библиотеки LuaJ доступны,
полноценной песочницы нет. Бесконечный цикл, исчерпание памяти и сбой JVM не изолированы.

## Docker

Нужен Docker. Сборка запускает тесты; Lua-файлы в финальном образе лежат отдельно от JAR.

```sh
docker build -t contract-lab .
docker run --rm contract-lab
```

Для изменения контракта на хосте без пересборки образа примонтируйте папку целиком.
Linux/macOS (bash):

```sh
docker run --rm -it --mount type=bind,source="$(pwd)/contracts",target=/app/contracts,readonly contract-lab --watch
```

Windows (PowerShell):

```powershell
docker run --rm -it --mount "type=bind,source=$($PWD.Path)/contracts,target=/app/contracts,readonly" contract-lab --watch
```

Меняйте `contracts/user.lua` на хосте; следующая проверка внутри контейнера увидит правку.
`readonly` запрещает запись из контейнера, но не мешает редактированию на хосте.
Если меняете также JSON, аналогично примонтируйте `examples` в `/app/examples`.

## Тесты и структура

```sh
mvn test
```

Автотесты проверяют PASS/FAIL, перезагрузку в том же движке, восстановление после ошибок Lua,
валидацию интерфейса функции, JSON/null/Unicode, независимость окружений,
реальные запросы к локальному HTTP-серверу, второй контракт и CLI-коды выхода.

```text
contract-lab/
  pom.xml
  Dockerfile
  README.md
  contracts/user.lua
  contracts/order.lua
  examples/user.json
  examples/user-invalid.json
  examples/order.json
  src/main/java/ru/lab/contract/
    Main.java
    ContractRunner.java
    JsonToLua.java
    ResponseSource.java
    DemoServer.java
  src/test/java/ru/lab/contract/ContractRunnerTest.java
```

Все обязательные требования покрыты: собственная основная программа, отдельное расширение,
изменение поведения без пересборки и инструкция с объяснением. Дополнительно реализованы
обновление без перезапуска, разные языки Java/Lua, обработка обычных ошибок и Dockerfile.
